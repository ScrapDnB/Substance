# Нативный слой macOS

Substance использует Qt Quick с оформлением macOS, нативными меню и системными диалогами. Основная панель инструментов подключена через AppKit `NSToolbar`: SF Symbols, `NSSegmentedControl` для режима, настройка состава кнопок и меню переполнения. Общие команды, горячие клавиши и проверка незавершённого ввода остаются в backend.

Кнопка боковой панели имеет `NSToolbarItem.isNavigational = true`. AppKit размещает её у левого края перед названием документа; простого первого места в списке toolbar недостаточно. Используется [публичный API AppKit](https://developer.apple.com/documentation/appkit/nstoolbaritem/isnavigational), доступный с macOS 11.

Стандартная компоновка `toolbar.v3` оставляет навигацию слева, центрирует переключатель режима через `centeredItemIdentifiers` и отделяет гибкими отступами правые группы команд: документ, undo/redo, медиа и экспорт. Новый идентификатор позволяет применить эту компоновку при переходе с предыдущей сборки; настройка состава toolbar по-прежнему доступна.

Подход сравнен с текущей локальной реализацией Dubbing Manager: `ui/macos_integration.py` и `qml_main.py`. В соседнем проекте есть незакоммиченные изменения, поэтому речь о рабочей копии. Файлы Dubbing Manager не изменялись.

Qt сохраняет исходные `NSWindow.contentView` и родителя своего вида. Нативная панель устанавливается до первого показа окна; при ошибке подключения используется QML-панель. На macOS 26+ боковая навигация — настоящий `NSGlassEffectView` стиля regular. `NSOutlineView`, SF Symbols, счётчики, `NSPopUpButton` и кнопка подключения медиа находятся внутри его `contentView`. Стекло используется только для навигации и системного toolbar; таблица, редактор и медиа сохраняют непрозрачные поверхности. Рекомендации Apple: [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass), [Build an AppKit app with the new design](https://developer.apple.com/videos/play/wwdc2025/310/).

В отличие от слоя `NSVisualEffectView` в Dubbing Manager, стекло не размещается фоном-соседом за QML-контролами: AppKit должен владеть содержимым стекла для правильной адаптации контраста. `NativeGlassSidebar` резервирует место в Qt SplitView и обновляет геометрию нативного вида на GUI-потоке после layout. Весь стеклянный компонент находится рядом с корневым видом Qt, выше него: `QNSView` экспортирует только Qt-дерево доступности и скрывает добавленные ему нативные дочерние виды. Такое размещение сохраняет иерархию Qt и делает навигацию доступной через macOS accessibility tree. При QML-диалогах вид скрывается, возвращая обычную боковую панель под модальным overlay. При закрытии отключаются backend-сигналы и удаляется нативный вид. Темы, активность окна, Reduce Transparency и системная адаптация материала остаются ответственностью AppKit; ручной blur и частные API не используются.

Доступность `NSGlassEffectView` проверяется во время выполнения. На macOS 15, Windows и в headless-режиме остаётся QML-навигация. Для проверки этого пути на новой macOS можно установить `SUBSTANCE_DISABLE_GLASS=1`. Минимум пакета остаётся **macOS 15**; macOS 13 не поддерживается текущим набором зависимостей.

`scripts/native_chrome_smoke.py` проверяет живое Cocoa-окно: указатели исходной иерархии, размеры, выбор реплики, ввод и фокус, передачу незавершённого текста при смене режима, блокировку неверного времени, действия undo/redo, темы и скрытие панели. Дополнительно проверяются native glass `contentView`, фильтры и выбор персонажа, восстановление выбора при ошибке ввода, перекрытие диалогами и освобождение вида. Тест использует свой цикл событий Qt, чтобы Python не удерживал GIL во время ожидания отрисовки Metal.

Проверка сборки `scripts/verify_macos_minimum.py` читает минимальные версии всех Mach-O файлов в пакете. Версия SDK не является минимальной версией ОС. Декларации в `Info.plist` недостаточно: Python, ffprobe, libass и их зависимости тоже должны поддерживать выбранную macOS.

`scripts/build.py` готовит загрузчик через `scripts/build_macos_bootloader.py`: исходники ровно установленной версии PyInstaller, текущий SDK 26+, deployment target 15. Исходники берутся из `build/bootloader-source` либо загружаются из PyPI с проверкой SHA-256. Установленный PyInstaller не меняется. Spec использует собственный загрузчик и подавляет понижение его SDK до версии SDK Python — стандартную эвристику PyInstaller для старого Tk, который Substance не использует. Сохраняется реально скомпилированная версия SDK; заголовки бинарников не подделываются для включения стекла. После упаковки отдельно проверяются SDK исполняемого файла и deployment targets всех зависимостей. Swift-библиотека не требуется.

Нативные toolbar и стеклянная боковая панель не входят в `QQuickWindow.grabWindow()`. Снимки Qt используются для проверки содержимого редактора; системный вид окна требует отдельного осмотра.
